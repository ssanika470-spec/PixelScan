This report covers the Week 4 performance optimization of the PixelScan front end. I started from an unoptimized baseline of the same page, with unminified CSS and JavaScript and a render-blocking script, and compared it with the optimized version. The optimizations were minifying CSS and JavaScript with a small build script, loading scripts with defer, using a system font stack instead of web fonts, replacing the logo and favicon with inline SVG and a data URI, drawing the dashboard chart with plain HTML and CSS instead of a charting library, applying content-visibility to off-screen sections, and adding cache headers for static hosting. The results were measured, not estimated. CSS and JavaScript for the home page dropped from 21,841 bytes to 17,610 bytes (19.4 percent smaller), and from 7,511 to 5,948 bytes after gzip (20.8 percent smaller). In a throttled Chromium lab test (375 pixel viewport, 150 ms latency, 1.6 Mbps, 4 times CPU slowdown, median of 12 runs), transferred bytes fell from 31,121 to 26,945 and first contentful paint moved from 594 ms to 568 ms. That timing gain is small and within normal variation, which I explain in the report: the page was already light, so the largest wins come from keeping it that way. The report also describes challenges, including a mobile layout overflow bug that I found and fixed during testing, and it includes a highlighted table for Lighthouse or PageSpeed Insights scores that must be run in the browser. The revised project files are in the linked GitHub repository.
