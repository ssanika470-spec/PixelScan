This report documents the accessibility audit and improvements I made to the PixelScan web interface for Week 3. I audited the landing page and the dashboard using a manual keyboard walkthrough, scripted structural checks, and WCAG 2.1 contrast calculations, and I verified the final behaviour with automated browser tests that ran in Chromium. The report lists each issue or risk, the WCAG success criterion it relates to, and the exact change I made. Key improvements include a skip-to-content link, proper landmarks (header, nav, main, footer), a single h1 with a logical heading order, a programmatically labelled file input, aria-live regions that announce file details and analysis results, a menu toggle that uses aria-expanded and aria-controls and closes with the Escape key while returning focus, and an accordion that follows the WAI-ARIA pattern with arrow, Home and End key support. Focus states use a 3 px outline, and all text and background pairs meet at least 6.8:1 contrast, well above the 4.5:1 AA requirement. The dashboard table uses real table markup with aria-sort on sortable headers. I also added support for reduced-motion preferences. All 21 automated checks passed, including keyboard-only operation of the menu, accordion and file inspector. The report is honest about its limits: it does not replace testing with real screen readers such as NVDA or VoiceOver, and the Lighthouse and WAVE scores must be run in the browser and entered in the highlighted table. The project code is in the linked GitHub repository.
